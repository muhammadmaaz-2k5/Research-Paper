# 🚀 Topic 1: Serverless Edge AI Cold-Start Elimination

### 📌 Target Professor:
* **Professor**: **Prof. Jianchun Liu** (*School of Computer Science & Technology, USTC*)
* **Email**: `jcliu17@ustc.edu.cn`
* **Research Focus**: Edge Computing, Software-Defined Networking, IoT, Containerized Cloud Systems

### 💥 The Pain Point (Short Explanation):
When running AI models inside serverless containers (Docker, AWS Lambda, Cloudflare Workers) at the edge, containers scale to zero when idle to save money. When a new user hits the API, the system takes **5 to 12 seconds** just to download container layers, boot Linux, and load PyTorch weights into RAM before generating the first token.

### 💡 The Research Solution:
Build a **Pre-Forked Shared Tensor Memory Pool**:
1. Host nodes pre-load common model weights into a centralized, memory-mapped (`mmap`) DRAM pool shared across all container namespaces.
2. An intelligent scheduling algorithm predicts incoming user bursts and pre-warms lightweight container execution forks **50ms before** the packet arrives.
3. Slashes cold-start latency from **8,000ms down to under 50ms** without keeping idle GPUs running.

### 📄 Proposal Title:
```text
Zero-Latency Serverless AI: Lightweight Memory-Mapped Container Forking for Heterogeneous Edge Computing
```

### 🗣️ 1-Minute Pitch Script:
> *"Prof. Liu, deploying AI microservices at the edge is crippled by 5-to-10 second container cold starts during scaling. Having architected containerized cloud backends and microservices for 4 years, I propose a shared memory-mapped tensor pooling framework that allows edge containers to fork instantly from a pre-warmed memory daemon. This slashes cold-start latency by over 90% without keeping idle GPUs running."*

# 🛡️ Topic 2: Invisible Watermarking and Copyright Protection for LLM Code

### 📌 Target Professor:
* **Professor**: **Prof. Kejiang Chen (陈可江)** (*School of Computer Science & Technology, USTC*)
* **Email**: `chenkj@ustc.edu.cn`
* **Research Focus**: Data Hiding, Adversarial Learning, Privacy Protection, Information Security

### 💥 The Pain Point (Short Explanation):
Millions of lines of code are generated daily by LLMs (Copilot, Claude, DeepSeek). Companies need to verify if code was generated by AI or stolen from proprietary codebases. However, existing text watermarks (swapping words) **break programming syntax and cause compiler errors** when applied to code.

### 💡 The Research Solution:
Build **AST-Preserving Logit Watermarking**:
1. Analyzes the Abstract Syntax Tree (AST) of the target programming language (TypeScript, Python) in real time during token generation.
2. Injects a cryptographic watermark only into **semantically invariant syntax structures** (e.g., mathematically equivalent loop constructs, deterministic whitespace entropy, or canonical variable alias hashing).
3. Produces code that executes identically and passes all linters, while embedding a mathematical signature detectable with 99.9% statistical confidence.

### 📄 Proposal Title:
```text
Syntax-Preserving Cryptographic Watermarking for Code Foundation Models Against Intellectual Property Theft
```

### 🗣️ 1-Minute Pitch Script:
> *"Prof. Chen, existing AI watermarking techniques fail on source code because lexical perturbations break compiler syntax and cause runtime bugs. Drawing on my software development background across multi-language codebases, I propose an AST-constrained logit biasing watermark that embeds mathematically provable ownership signatures exclusively into semantically invariant code structures without altering execution behavior."*

* **Email**: `hchen@ustc.edu.cn`
* **Research Focus**: Big Knowledge Engineering, Data Mining, Machine Learning

### 💥 The Pain Point (Short Explanation):
Non-technical managers want to ask questions in plain English (*"Show all clients in Germany who canceled after the price hike"*) and have an LLM write the SQL query. However, enterprise databases have **hundreds of tables and complex foreign keys**. Standard LLMs hallucinate non-existent column names and create invalid multi-table JOINs that crash databases.

### 💡 The Research Solution:
Build a **Relational Graph-Constrained Decoding Framework**:
1. Parses SQL DDL schemas and database transaction logs to construct a directed **Relational Knowledge Graph** linking tables, foreign keys, cardinality, and business rules.
2. During token generation, the LLM is constrained to only output SQL tokens (table names, JOIN conditions) that follow valid paths in the Knowledge Graph.
3. Guarantees 100% syntactically valid SQL queries with zero schema hallucinations.

### 📄 Proposal Title:
```text
Relational Graph-Constrained Decoding: Eliminating Hallucinations in Multi-Table Enterprise Text-to-SQL Generation
```

### 🗣️ 1-Minute Pitch Script:
> *"Prof. Chen, standard LLM Text-to-SQL pipelines fail in enterprise deployments because vector similarity cannot capture relational foreign-key constraints across multi-table databases. Building upon Big Knowledge Engineering principles, I propose an automated Schema-to-Graph compiler that constrains LLM decoding along verified relational graph paths, ensuring 100% mathematically valid SQL queries without schema hallucinations."*
